# 🛠️ SocialSpark AI - Bug Fixes & Improvements Log

This document records the functional and architectural issues discovered during end-to-end testing, along with the precise resolutions implemented across the codebase.

---

## 1. Input Validation & Edge Case Handling (Backend & Netlify Functions)
- **Problem**: Missing or empty fields (e.g. empty brand name, missing category, empty platform array) were previously accepted and passed down into the Gemini prompt or fallback generator with unhelpful defaults.
- **Resolution**:
  - Implemented strict validation checks in `server.ts` and `netlify/functions/api.ts`.
  - Brand Name requires length between 2 and 100 characters.
  - Required validation on `businessCategory`, `targetAudience`, and `brandVoice`.
  - Enforced at least one selected social media platform.
  - Enforced a hard 500-character cap on `additionalInstructions`.
  - Return clean HTTP `400 Bad Request` with actionable error descriptions.

---

## 2. Gemini Prompt & Schema Hardening
- **Problem**: In rare cases, LLM responses could produce fewer than 7 days, disordered days, or duplicate day entries.
- **Resolution**:
  - Updated prompt to explicitly instruct generation of exactly 7 distinct days in chronological order (`Monday`, `Tuesday`, `Wednesday`, `Thursday`, `Friday`, `Saturday`, `Sunday`).
  - Added deterministic normalization and sanitization post-processing: iterates through all 7 canonical days and verifies each day contains required fields (`day`, `platform`, `contentType`, `idea`, `time`, `cta`, `caption`, `hashtags`, `engagementTip`).
  - Standardized model usage to `gemini-2.5-flash` with JSON schema enforcement.

---

## 3. UI State Leaks & Stale Closures across Generations
- **Problem**: When generating a plan for Brand A, then returning to the generator and creating a plan for Brand B, the local `schedule` state in `ResultSection.tsx` previously failed to synchronize because `useState` was only evaluated on first mount.
- **Resolution**:
  - Added a `useEffect` dependency listener in `src/components/ResultSection.tsx`:
    ```tsx
    useEffect(() => {
      if (generatedData?.calendar && generatedData.calendar.length > 0) {
        setSchedule(generatedData.calendar);
      }
    }, [generatedData]);
    ```
  - Prevents stale card data from leaking across multiple generations.

---

## 4. Multi-View Architecture (Detailed, Calendar, Kanban)
- **Problem**: The interface previously only offered a single vertical card stack, making quick scheduling review across the 7 days cumbersome on tablets and desktops.
- **Resolution**:
  - Added a responsive **View Switcher** (`Cards`, `Calendar`, `Kanban`).
  - **Calendar Grid**: 7 responsive day boxes with date badges, optimal times, CTAs, and format indicators.
  - **Kanban Board**: Structured columns ("Early Week Momentum", "Mid-Week Engagement", "Weekend Community") with quick modal dialogs.
  - Seamless switching without data loss or card duplication.

---

## 5. Live AI vs. Deterministic Fallback Mode Transparency
- **Problem**: Users and evaluators could not clearly determine if an output was generated by a live Gemini API call or by the deterministic fallback mode.
- **Resolution**:
  - Added `isFallback` and `source` (`'ai' | 'fallback'`) properties to `GeneratedResult`.
  - If in fallback/demo mode: displays a polite banner explaining demo status and how to provide `GEMINI_API_KEY`.
  - If in live AI mode: displays a green verified badge confirming live Gemini AI generation.

---

## 6. Clipboard Copying in Iframes
- **Problem**: In restricted iframes (such as sandbox preview environments), `navigator.clipboard.writeText` can throw security errors.
- **Resolution**:
  - Added an automated fallback in `src/services/api.ts` using a hidden `textarea` and `document.execCommand('copy')`, ensuring copy buttons work reliably in all browser contexts.

---

## 7. Print & PDF Export Formatting
- **Problem**: Browser print output included navigation bars, buttons, and misaligned cards.
- **Resolution**:
  - Added `@media print` rules in `src/index.css`.
  - Standardized `.print:hidden` classes on header, footer, interactive buttons, and notifications.
  - Styled printed cards with clean page breaks and high-contrast typography suitable for client PDF export.

---

## 8. Footer Link Styling & Navigation Alignment
- **Problem**: The "AI Content Planner" footer link was bolded while other links were regular weight, and clicking it did not consistently scroll and reset the view.
- **Resolution**:
  - Removed font-bold weight from `src/components/Footer.tsx`.
  - Wired navigation callback in `src/App.tsx` to set `activeTab = 'generator'`, `isGenerated = false`, and smooth-scroll to `(0, 0)`.
